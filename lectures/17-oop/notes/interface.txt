# Java Inheritance, `super`, and `final`

This note explains the basics of inheritance in Java, how constructors work when inheritance is involved, and how the `super` and `final` keywords are used.

---

## 1. Basics of Inheritance

Inheritance allows a child class to reuse the properties and methods of a parent class. In Java, we use the `extends` keyword for this.

```java
class SubclassName extends SuperclassName {
    // Body of the subclass
}
```

### Important Rules

* **Single Inheritance:** A class can extend only one other class. Java does not allow a class to directly extend multiple classes.
* **No Self-Inheritance:** A class cannot extend itself.
* **Private Members:** A child class cannot directly access the parent's `private` variables or methods.

---

## 2. Parent Reference and Child Object

A reference variable of the parent class can point to an object of the child class.

```java
Superclass ref = new Subclass();
```

For example:

```java
// plainbox is a parent-class reference
// weightbox is a child-class object

Superclass ref = new Subclass();
```

### The Important Rule

What you can access depends on the **type of the reference variable**, not the actual object.

So, if `ref` is declared as `Superclass`, you can only access the methods and variables available in `Superclass`.

The child object may have additional methods, but you cannot access those methods directly through the parent reference.

---

## 3. The `super` Keyword

The `super` keyword is mainly used in two situations.

### Use 1: Calling the Parent Constructor

`super()` is used to call a constructor of the parent class.

It must be the **first statement** inside the child class constructor.

```java
class BoxWeight extends Box {

    BoxWeight(BoxWeight ob) {
        super(ob); // Calls the parent class constructor
        this.weight = ob.weight;
    }
}
```

Here, `super(ob)` passes the object to the constructor of the `Box` class.

---

### Use 2: Accessing Parent Members

`super` can also be used to access a variable or method from the parent class.

This is especially useful when the parent and child classes have variables with the same name.

```java
super.member;
```

Here, `member` can be a variable or a method belonging to the parent class.

You can think of it like this:

* `this` → refers to the current object
* `super` → refers to the parent-class part of the object

---

## 4. Constructor Execution Order

When inheritance is involved, the **parent constructor runs first**, and then the child constructor runs.

For example:

```java
class Parent {
    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {
    Child() {
        System.out.println("Child constructor");
    }
}
```

When we create:

```java
Child obj = new Child();
```

The output will be:

```text
Parent constructor
Child constructor
```

### Why does this happen?

1. The parent class needs to initialize its own part of the object first.
2. The parent constructor runs before the child constructor.
3. If you don't write `super()` yourself, Java automatically inserts a call to the parent's **no-argument constructor**.
4. If the parent only has a parameterized constructor, the child must explicitly call it using `super(arguments)`.

---

## 5. The `final` Keyword

The `final` keyword is mainly used to prevent something from being changed, overridden, or inherited.

It can be used with variables, methods, and classes.

### 1. `final` Variable

A `final` variable cannot be reassigned after it has been given a value.

```java
final int MAX = 100;
```

You cannot later do:

```java
MAX = 200; // Error
```

This is commonly used when creating constants.

---

### 2. `final` Method

A method marked as `final` cannot be overridden by a child class.

```java
class Parent {

    final void show() {
        System.out.println("Hello");
    }
}
```

A child class cannot create another version of `show()`.

> Note: `final` methods can help the JVM optimize calls in some situations, but don't use `final` simply because you expect a performance improvement.

---

### 3. `final` Class

A `final` class cannot be extended by another class.

```java
final class Parent {
    // class body
}
```

This is not allowed:

```java
class Child extends Parent {
    // Error
}
```

Also remember:

* A class cannot be both `abstract` and `final`.
* `abstract` means the class is designed to be extended.
* `final` means the class cannot be extended.

So the two ideas contradict each other.

---

## 6. Quick Notes to Remember

### Static Methods

Static methods are associated with the class rather than individual objects.

They can appear to be inherited, but they are **not overridden** like normal instance methods.

If a child class defines a static method with the same signature as the parent, the method that gets called depends on the **reference type**, not the actual object.

---

### Static Interface Methods

Static methods declared inside an interface are **not inherited** by implementing classes.

They should be called using the interface name.

```java
InterfaceName.methodName();
```

---

### Variables and Polymorphism

Polymorphism works with **methods**, not instance variables.

Instance variables cannot be overridden. If a child class declares a variable with the same name as one in the parent class, the variables are simply **hidden/shadowed**.

So remember:

> **Methods → overridden**
> **Variables → hidden/shadowed**

## Quick Revision

| Concept            | Remember                       |
| ------------------ | ------------------------------ |
| `extends`          | Used for inheritance           |
| `super()`          | Calls the parent constructor   |
| `super.variable`   | Accesses the parent's variable |
| `super.method()`   | Calls the parent's method      |
| Parent constructor | Runs before child constructor  |
| `final` variable   | Cannot be reassigned           |
| `final` method     | Cannot be overridden           |
| `final` class      | Cannot be extended             |
| Static method      | Not overridden                 |
| Instance variable  | Not overridden                 |
| Polymorphism       | Mainly applies to methods      |
