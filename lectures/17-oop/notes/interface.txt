# 🧬 Java Inheritance, `super`, and `final`

This guide covers the core mechanics of class inheritance, constructor chaining, member access rules, and control modifiers in Java.

---

## 1. Core Basics of Inheritance

Inheritance allows one class to incorporate the definition of another class using the **`extends`** keyword.

```java
class SubclassName extends SuperclassName { 
    // Body of the subclass 
}
```

### 🚫 Key Restrictions
* **Single Inheritance Only**: You can only specify one superclass for any subclass. Java does not support multiple inheritance of classes.
* **No Self-Inheritance**: A class cannot be a superclass of itself.
* **Private Member Access**: A subclass includes all members of its superclass, but it **cannot** directly access private members.

---

## 2. Superclass Variables & Subclass Objects

A superclass reference variable can reference any object derived from that class. 

### ⚠️ Crucial Reference Rule
The **type of the reference variable** determines which members can be accessed, *not* the type of the object being referenced.

```java
// planebox is a Superclass variable, weightbox is a Subclass object
plainbox = weightbox; 

Superclass ref = new Subclass(); 
// 'ref' can only access methods and variables declared in Superclass
```

---

## 3. The `super` Keyword

The keyword `super` has two distinct use cases in Java.

### Use Case A: Calling a Superclass Constructor
It invokes the constructor of the immediate superclass. It must always be the **first statement** inside the subclass constructor.

```java
class Box {
    private double width, height, depth;

    Box(Box ob) {
        this.width = ob.width;
        this.height = ob.height;
        this.depth = ob.depth;
    }
}

class BoxWeight extends Box {
    double weight;

    BoxWeight(BoxWeight ob) {
        super(ob); // Passes BoxWeight object to Box(Box ob) constructor
        this.weight = ob.weight;
    }
}
```

### Use Case B: Accessing Hidden Superclass Members
It acts like `this`, but always points to the immediate superclass. This helps when subclass member names **hide** (shadow) superclass members.

```java
super.member // 'member' can be a method or an instance variable
```

---

## 4. Constructor Execution Order

Constructors always complete execution in **order of derivation** (from superclass to subclass).

### ⚙️ How it Works
1. A superclass has no knowledge of subclasses. 
2. Superclass initialization must happen first as a prerequisite.
3. If `super()` is omitted, Java automatically executes the **default/parameterless** constructor of the superclass.
4. If a superclass constructor requires parameters, all subclasses **must** explicitly pass those parameters up the line.

---

## 5. Using `final` with Inheritance

The `final` keyword has three distinct applications:

### #1 Creating Named Constants
Prevents the value of a variable from being altered after initialization.

### #2 Preventing Method Overriding
Methods declared as `final` cannot be overridden by subclasses.

* **Early Binding (Performance Boost)**: Standard methods use *late binding* resolved at run time. `final` methods cannot change, so the compiler uses *early binding* at compile time.
* **Inlining**: The compiler can copy the bytecode of a small `final` method directly into the calling code, eliminating method call overhead.

### #3 Preventing Class Inheritance
Precede a class declaration with `final` to stop other classes from extending it.

* **Implicit Final**: Declaring a class as `final` implicitly makes all its methods `final` too.
* **Illegal Combination**: A class cannot be both `abstract` and `final`. Abstract classes are incomplete and rely entirely on subclasses to implement them.

---

## 💡 Important Quick Notes

* **Static Methods**: Static methods can be inherited, but overriding them does nothing. The parent class version always runs based on the reference type. 
* **Static Interfaces**: Static interface methods do not get inherited at all. They must have a body and must be called directly using the interface name.
* **Polymorphism Shadowing**: Polymorphism applies strictly to methods. **Polymorphism does not apply to instance variables.**
